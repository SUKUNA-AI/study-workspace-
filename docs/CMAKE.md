# Локальная сборка программ

Нужны CMake 4.4, Ninja и компилятор с поддержкой C++23 и `import std;`.
В текущем окружении используются GCC 16 и libstdc++.

Создавай собственные программы в `U01`, `U02`, `u01`, `u02` и других
папках вида `U<число>` или `u<число>`. Вложенность произвольная.
Каждый `.cpp` — отдельная программа со своим `main()`:

| Исходник | Цель сборки и запуска |
| --- | --- |
| `U01/reading/1.cpp` | `U01_reading_1` |
| `U01/reading/2.cpp` | `U01_reading_2` |
| `u02/practice/1.cpp` | `u02_practice_1` |
| `u03/hello.cpp` | `u03_hello` |

Имя цели получается из пути без `.cpp`: разделители и знаки препинания
заменяются на `_`. Если два пути дают одинаковое имя, CMake сообщит об этом;
переименуй файл или папку. Одинаковые имена файлов в разных папках допустимы.
Многофайловому проекту с одним `main()` нужна отдельная настройка CMake.

Из корня workspace:

```bash
cmake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug --target U01_reading_1 --parallel 2
./build/debug/bin/U01_reading_1
```

Для сборки всех программ: `cmake --build build/debug --parallel 2`.
`-B` может указывать на другой каталог, в том числе за пределами workspace.
При первой сборке CMake также собирает стандартный модуль `std`.

Существующая конфигурация CLion `study_workspace_` собирает и запускает
`U01/reading/1.cpp`. Её исполняемый файл остаётся в корне каталога сборки.
Чтобы назначить ей другой исходник, укажи при настройке
`-DSTUDY_STARTUP_SOURCE=u02/practice/1.cpp`. Для остальных программ можно
выбирать их отдельные цели из таблицы выше.

В CLion открой корневой `CMakeLists.txt`, выполни **Reload CMake Project**
и выбери нужную цель, например `U01_reading_1`, в списке конфигураций запуска.
После создания новой папки или `.cpp` повтори Reload: появится новая цель.
В диалоге создания файла не добавляй новый `.cpp` в существующую цель:
для программы со своим `main()` CMake автоматически создаёт отдельную цель.
Например, для запуска `2.cpp` выбирай `U01_reading_2`.
При переходе со старой настройки, если CMake сообщает, что `import std`
не был включён при обнаружении компилятора, выполни **Reset Cache and Reload Project**
(в терминале — настройку с `cmake --fresh -S . -B build/debug -G Ninja`).
При сборке из терминала добавления и удаления исходников подхватываются
автоматически. Незавершённая программа может сломать сборку всех целей;
выбирай конкретную цель, чтобы собирать только её.

`materials/`, проверочные программы курса и служебные каталоги в эту сборку
не входят. Эта сборка и запуск не заменяют проверку задания через judge.
