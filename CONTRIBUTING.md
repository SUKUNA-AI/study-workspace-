# Как предложить исправление

Форма ошибок и вопросов: [создать публичное сообщение](https://github.com/SUKUNA-AI/study-workspace-/issues/new?template=course-feedback.yml).
Выбери область, укажи ID задания/шага, ревизию материалов, шаги воспроизведения,
ожидаемый и фактический результат. Вопрос к ревью дополнительно содержит ID критерия.
Поля формы публичны: прикладывай только разрешённый пример; токены, личные черновики,
закрытые проверки и книги сохраняются вне сообщения.

Для изменения файлов:

1. Открой нужный публичный репозиторий и нажми **Fork**.
   Обвязка и инструкции находятся в [study-workspace-](https://github.com/SUKUNA-AI/study-workspace-),
   экспортированные условия — в [study-materials](https://github.com/SUKUNA-AI/study-materials).
2. Клонируй свой fork с материалами: `git clone --recurse-submodules <URL своего fork>`.
   Создай отдельную ветку: `git switch -c fix/<короткое-имя>`.
3. Внеси небольшое изменение. Сохрани stable IDs и канонический путь работы.
   Публичные материалы генерируются: их diff служит предложением; сопровождающий
   переносит одобренную правку в канонический источник и пересобирает экспорт.
4. Выполни относящиеся к изменению локальные проверки. Запиши команды, коды выхода,
   исходную ревизию и конкретный регрессионный пример. Невыполненное обозначь `not_run`.
5. На GitHub открой **Compare & pull request** в исходный публичный репозиторий.
   Заполни шаблон: проблема, связанный issue, влияние на ученика, ревизия и проверки.

PR внешнего участника — предложение к платформе. Личный прогресс находится в
авторизованном аккаунте владельца; внешний PR его не меняет. Проверки и доступ
к домашнему GPU назначает сопровождающий после отдельного рассмотрения.
Публичный PR не получает секретов и права запуска на домашнем стенде.
Изменения `.gitmodules`, checker, `AGENTS.md` и политики доверия рассматриваются
как изменение обвязки отдельно от учебного решения.

После исправления сопровождающий указывает доставленную ревизию и результат
повторного регрессионного сценария. Автор сообщения проверяет новую ревизию;
issue закрывается после подтверждения результата. Старый зелёный лог сохраняет
свою исходную версию и не подтверждает изменённый выпуск.

Учебная сдача описана в `docs/WORKFLOW.md`: пробный запуск в браузере выполняется
через портал; итоговый обязательный исходник хранится по каноническому пути workspace.
Публичный доступ к файлам не предоставляет дополнительных лицензионных прав.
